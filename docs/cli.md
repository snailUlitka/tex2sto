# Командная строка

## Проверка исходника

```sh
tex2sto check document.tex
tex2sto check document.tex --strict
```

`check` раскрывает локальные `\input`, разбирает метаданные и проверяет весь
диалект, но не запускает Pandoc. Обычный режим допускает предупреждения;
`--strict` превращает их в ошибки.

## Сборка

```sh
tex2sto build document.tex
tex2sto build document.tex -o output
```

DOCX создаётся всегда. Каталог по умолчанию — `build` рядом с главным
исходником; относительный путь `-o` разрешается от текущего рабочего каталога.

Флаг `--pdf` дополнительно создаёт экспериментальный предварительный PDF. Этот
формат не входит в гарантии совместимости версии 2.0 и может отличаться от DOCX
по составу служебных страниц и вёрстке.

Общие параметры сборки:

- `--strict` — считать предупреждения ошибками;
- `--numbering auto|global|section` — общая политика нумерации рисунков,
  таблиц и формул;
- `--numbering-threshold N` — порог режима `auto`, по умолчанию 10;
- `--figure-numbering`, `--table-numbering`, `--equation-numbering` — переопределить
  политику для отдельного типа объекта.

В режиме `auto` тип объектов получает нумерацию по разделам, если документ
имеет не менее двух разделов, объекты этого типа встречаются хотя бы в двух из
них, а общее число объектов достигает порога. Иначе используется сквозная
нумерация. Объекты приложений всегда имеют локальные номера вида `А.1`.

## Настройки и проверка объёма

Параметры берутся из `tex2sto.toml` рядом с главным исходником.
`--config другой.toml` выбирает другой файл. Явные флаги имеют приоритет;
`--no-strict` и `--no-pdf` отключают соответствующие настройки.
Полный перечень приведён в [справке по конфигурации](configuration.md).

После рендера документа в PDF выполните:

```sh
tex2sto check-pages document.tex rendered.pdf
```

Лимиты `pages.minimum` и `pages.maximum` по умолчанию не заданы. Команда
использует `pdfinfo` из Poppler и выдаёт предупреждения по фактическому числу
страниц переданного PDF. `--strict` превращает их в ошибки. Рендер DOCX
выполняется отдельно; LibreOffice не входит в путь сборки.

## Коды завершения

- `0` — проверка или сборка завершена;
- `1` — исходник содержит диагностические ошибки либо предупреждения в
  `--strict`;
- `2` — исходник невозможно прочитать или внешний инструмент отсутствует,
  имеет неверную версию либо завершился с ошибкой.

Диагностика имеет стабильный идентификатор, например `T2S-E101` для ошибки и
`T2S-W103` для предупреждения. Чтобы подавить допустимое предупреждение на
следующей содержательной строке, укажите один или несколько кодов:

```tex
% tex2sto: ignore=T2S-W103,T2S-W104
В испытании использовано 3~мм материала.
```

Подавление действует только на следующую непустую строку, не являющуюся
комментарием. Ошибки подавлять нельзя.

## Поля Word

DOCX содержит поля числа страниц и номеров страниц содержания. Надписи
продолжения таблиц формируются при сборке. Word получает настройку обновить их при открытии. Если приложение
показывает запрос на обновление полей, подтвердите его; после крупных ручных
правок выделите документ и выполните «Обновить поле».
