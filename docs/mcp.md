# MCP-сервер

`tex2sto-mcp` позволяет локальному агенту получить справку по диалекту и собрать
редактируемый DOCX из существующего `.tex`-проекта. Сервер работает через
`stdio`: MCP-клиент запускает его как отдельный процесс. Для сборки нужен
Pandoc 3.11, как и при использовании CLI.

После установки проекта (`uv sync`) укажите клиенту исполняемый файл из
виртуального окружения. Например, запись для клиента с форматом `mcpServers`:

```json
{
  "mcpServers": {
    "tex2sto": {
      "command": "/абсолютный/путь/к/tex2sto/.venv/bin/tex2sto-mcp"
    }
  }
}
```

Путь к команде замените на путь в своей системе. Если клиент поддерживает
настройку рабочего каталога MCP-процесса, задайте каталог проекта. Иначе
передавайте абсолютные пути: относительные `source` и `output_dir` отсчитываются
от рабочего каталога процесса сервера. Для запуска через Docker смонтируйте
каталог исходников и откройте стандартный ввод:

```sh
docker run --rm -i -v "$PWD:/work" \
  --entrypoint /app/.venv/bin/tex2sto-mcp tex2sto:2.0.0
```

В настройке MCP-клиента для Docker передайте эквивалентные аргументы команде
`docker`, заменив `$PWD` абсолютным путём к каталогу исходников.

## Справка по диалекту

Инструмент `get_dialect_docs()` возвращает краткое описание на русском языке,
абсолютный путь `documentation_path` к полному файлу и URI
`documentation_uri`. Полный текст доступен как MCP-ресурс
`tex2sto://dialect/v2` с типом `text/markdown`. Он соответствует
[документации диалекта](dialect.md) установленной версии.

## Сборка DOCX

Инструмент `build_docx` принимает путь `source` к главному `.tex`-файлу.
Настройки читаются из `tex2sto.toml` рядом с главным исходником. Неуказанные
параметры наследуют конфиг; явно переданные значения имеют приоритет.
Поддерживаются параметры:

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `config` | `tex2sto.toml` рядом с главным файлом | Другой путь конфигурации |
| `output_dir` | `build` рядом с главным файлом | Каталог результата |
| `strict` | `false` | Считать предупреждения ошибками |
| `numbering` | `auto` | Общий режим: `auto`, `global` или `section` |
| `numbering_threshold` | `10` | Порог автоматического режима |
| `figure_numbering` | не задан | Режим для рисунков |
| `table_numbering` | не задан | Режим для таблиц |
| `equation_numbering` | не задан | Режим для формул |

Успешный ответ содержит абсолютный путь `docx_path`, список созданных файлов `outputs` и массив `warnings`.
Каждое предупреждение содержит `code`, `severity`, `message`, `path` и `line`.
Ошибки исходника, строгого режима и внешних инструментов возвращаются как ошибка
MCP-инструмента с диагностикой; при ошибке валидации DOCX не создаётся.
Если в конфиге задано `build.pdf = true`, дополнительно создаётся
экспериментальный PDF; оба пути входят в `outputs`.

## Настройки и проверка страниц

Ресурс `tex2sto://configuration/v2` содержит полное описание конфигурации,
типов и значений по умолчанию. Его URI возвращается в `configuration_uri`
инструмента `get_dialect_docs`.

Инструмент `check_pages(source, rendered_pdf, config?, strict?)` проверяет
лимиты страниц по уже отрендеренному PDF. Он возвращает `pages` и `warnings`.
Для чтения PDF нужен Poppler `pdfinfo`. Настройки и строгий режим совпадают
с CLI `check-pages`; сам инструмент не запускает рендер DOCX.
