# Диалект tex2sto 2.0

Диалект намеренно уже LaTeX. Неизвестная команда или окружение — ошибка;
визуальное оформление принадлежит профилю `ssau` с локальными
[настройками проекта](configuration.md). В частности, нельзя применять
`\textbf`, `\underline`, произвольные пакеты, TikZ или собственные команды.

## Каркас и метаданные

Главный файл обязан содержать ровно один `\documentclass{tex2sto}` и одно
окружение `document`. До него задаются метаданные выбранного вида работы.

### Лабораторная работа

Базовый титульник лабораторной задаётся одной командой `\labtitle{...}` после
`\documentclass{tex2sto}` и до `\begin{document}`:

```tex
\documentclass{tex2sto}
\labtitle{
  number={3},
  course={Моделирование информационно-вычислительных систем},
  variant={17},
  author={Иванов И. И.},
  group={6402-090301D},
  reviewer={Петрова Е. В.},
  reviewer-label={Проверила},
  year={2026}
}

\begin{document}
\section{Задание}
Текст задания и отчёта.
\end{document}
```

| Параметр | Содержание | Обязательность |
| --- | --- | --- |
| `number` | Номер лабораторной, положительное целое число | Да |
| `course` | Название курса без внешних кавычек | Да |
| `author` | ФИО автора в требуемой форме | Да |
| `group` | Номер группы без префикса «гр.» | Да |
| `reviewer` | ФИО проверяющего, при необходимости с должностью | Да |
| `year` | Год из четырёх цифр | Да |
| `variant` | Обозначение варианта без префикса «Вариант №» | Нет, строка отсутствует |
| `city` | Город | Нет, по умолчанию `Самара` |
| `author-label` | Подпись перед автором, например `Выполнила` | Нет, по умолчанию `Выполнил` |
| `reviewer-label` | Подпись перед проверяющим, например `Проверила` | Нет, по умолчанию `Проверил` |

Параметры именованные: порядок произвольный, каждое значение заключают в
фигурные скобки, между параметрами ставят запятую. Последняя запятая допустима.
Запятая внутри значения, например в должности проверяющего, остаётся частью
текста. Необязательные поля пропускают целиком: пустые значения, повторные и
неизвестные параметры считаются ошибками. Команда допустима ровно один раз.

В значениях разрешён обычный текст, `~` для неразрывного пробела и экранированные
символы `\%`, `\&`, `\#`, `\_`, `\{`, `\}`. Команды форматирования,
математика и вложенные группы не поддерживаются. Комментарий `% ...` действует
до конца строки; для печатного процента используют `\%`.

Профиль сам добавляет шапку университета, название отчёта, кавычки вокруг курса,
строку варианта, подписи и город с годом. ФИО и группа располагаются отдельными
абзацами справа. В DOCX город и год находятся в отдельном колонтитуле первой
страницы и остаются редактируемыми. Титульник учитывается в нумерации, но номер
на нём не печатается; основной текст начинается со следующей страницы.

Для лабораторной обязателен хотя бы один `\section`. Введение и заключение
необязательны; если они есть, их размещают до и после основной части
соответственно. Реферат, содержание и страницы задания ВКР не создаются.
`\labtitle` нельзя сочетать с отдельными командами метаданных ВКР, включая
`\title`, `\author`, `\year`, `\keywords`, команды задания и окружение
`abstract`. Источники, ссылки и остальные элементы основного текста доступны
по общим правилам. Этот вариант рассчитан на одного автора и одного
проверяющего; другие формы титульника пока не выбираются параметром.

Готовый исходник: [пример лабораторной](../examples/lab-report/main.tex).

### Выпускная квалификационная работа

Без `\labtitle` используется прежняя структура ВКР. Метаданные задаются
отдельными командами:

```tex
\documentclass{tex2sto}
\title{Название работы}
\author{Иванов Иван Иванович}
\studentgroup{6401-090301D}
\institute{Институт информатики и кибернетики}
\faculty{Факультет информатики}
\department{Кафедра программных систем}
\programcode{09.03.01}
\programname{Информатика и вычислительная техника}
\studyprofile{Профиль подготовки}
\supervisor{Петров П. П.}{доцент, к.т.н.}
\normcontroller{Кузнецова Н. Н.}
\city{Самара}
\year{2026}
```

Обязательны `title`, `author`, `studentgroup`, `institute`, `department`,
`programcode`, `programname`, `studyprofile`, `supervisor`, `normcontroller` и
`year`. `faculty` необязателен, `city` по умолчанию равен `Самара`. Каждая
одиночная команда может встретиться только один раз.

Задание выбирается командой `\assignmentvariant{none|1|2}`. Для вариантов 1 и
2 обязательны `\assignmentapprover`, `\assignmentquestions`,
`\assignmentissued` и `\assignmentdue`; `\assignmentgoal` необязателен.
Повторяемая команда `\consultant{ФИО}{роль}` выводится на второй странице
варианта 2.

Реферат задаётся ровно одним окружением `abstract`. Рекомендуемый предел — 850
символов. `\keywords{...}` содержит от 5 до 15 элементов через точку с запятой:

```tex
\keywords{ДОКУМЕНТ; КОНТРОЛЬ; МОДЕЛЬ; ВАЛИДАЦИЯ; АВТОМАТИЗАЦИЯ}
\begin{abstract}
Краткое описание объекта, цели, результатов и области применения.
\end{abstract}
```


### Отчёт по практике

Команда `\practicetitle{...}` выбирает титульник практики и задание с таблицей
компетенций. Обычные метаданные ВКР (`title`, `author`, `studentgroup`, `institute`,
`department`, `programcode`, `programname`, `studyprofile`, `supervisor`, `year`)
сохраняются; `normcontroller` для практики необязателен. Реферат, ключевые слова,
содержание, введение и заключение обязательны. `\labtitle` и варианты задания
ВКР не сочетаются с этим видом документа.

```tex
\practicetitle{
  kind={учебная}, type={технологическая (проектно-технологическая)},
  start={2026-10-01}, end={2026-11-30},
  order-date={2026-09-30}, order-number={100-ПР},
  organization={Кафедра информационных систем и технологий},
  author-dative={Иванову Ивану Ивановичу},
  submitted={2026-11-30}, defended={2026-11-30}
}
\practiceassignment{Компетенция}{Планируемые результаты}{Содержание задания}
```

В `practicetitle` обязательны `kind`, `type`, `start`, `end`, `order-date`,
`order-number`, `organization`, `author-dative`. Необязательны `study-level`
(по умолчанию `магистратуры`), `submitted`, `defended`, `grade`. При отсутствии
дат сдачи, защиты и оценки выводятся места для заполнения. Даты задаются
в формате `YYYY-MM-DD` и печатаются как `ДД.ММ.ГГГГ`; начало не может быть позже
окончания. ФИО в дательном падеже задаёт автор: программа его не склоняет.

Значения являются обычным текстом с теми же правилами экранирования, что у
`labtitle`. Объявление допустимо один раз между `documentclass` и `document`.
Хотя бы одна команда `practiceassignment` обязательна; все три аргумента
непустые. Каждая команда в преамбуле создаёт строку редактируемой таблицы
задания. Головка таблицы повторяется при переносе; служебной таблице задания
не требуются подпись и ссылка из основной части. `assignmentissued` и
`assignmentdue` позволяют заменить печатные даты выдачи и сдачи задания;
без них используются начало и окончание практики.

[Пример практики](../examples/practice-report/main.tex) содержит локальный
`tex2sto.toml`. Он показывает синтаксис, а не выполнение требований к объёму
или содержательному освоению компетенций.

## Структура документа

Поддерживаются:

- `\definitions` и повторяемая `\definition{термин}{определение}`;
- `\abbreviations` для последующего перечня сокращений;
- `\introduction`;
- `\section{...}`, `\subsection{...}`, `\subsubsection{...}`;
- `\paragraph{...}` и `\subparagraph{...}`;
- `\conclusion`;
- `\printbibliography`;
- `\appendix{app:метка}{Название}`.

Для ВКР введение, хотя бы один раздел и заключение обязательны и идут в этом
порядке. Для лабораторной с `\labtitle` обязателен только раздел, а порядок
необязательных введения и заключения сохраняется.
По умолчанию определения и сокращения размещаются до введения.
`structure.terminology_position = "after-conclusion"` разрешает размещение
после заключения перед источниками и приложениями. Список источников идёт после
заключения, приложения — после списка источников либо после заключения, если
источников нет. Заголовок раздела начинается с прописной буквы и не заканчивается
точкой. Каждый структурный элемент и каждый раздел верхнего уровня начинается
с новой страницы. У нумерованных заголовков отступ первой строки — 1,25 см.

Если присутствуют определения, обозначения или сокращения, команды
`\definitions` и `\abbreviations` открывают один общий структурный элемент
`ОПРЕДЕЛЕНИЯ, ОБОЗНАЧЕНИЯ И СОКРАЩЕНИЯ`. Каждая команда допустима не более
одного раза; отдельная страница между двумя частями не создаётся.

Приложения объявляются в порядке первого упоминания в основном тексте. Метка
начинается с `app:`. 2.0 использует допустимые одиночные буквы `А`, `Б`, `В`, `Г`,
`Д`, `Е`, `Ж`, `И`, `К`, `Л`, `М`, `Н`, `П`, `Р`, `С`, `Т`, `У`, `Ф`, `Х`, `Ц`,
`Ш`, `Щ`, `Э`, `Ю`, `Я`; внутренние заголовки и объекты получают префикс
приложения.

## Текст, ссылки и включения

В тексте разрешены `\emph{...}`, `\texttt{...}`, `\href{URL}{текст}`,
`\url{URL}`, `\newline` и `\ldots`. Неразрывный пробел пишется `~`. Команда
`\input{path}` включает UTF-8 `.tex` относительно текущего файла; расширение
можно опустить. Абсолютные пути, выход из каталога главного файла, отсутствующие
файлы и циклы запрещены.

`\label{prefix:name}` задаёт метку, `\ref{prefix:name}` — ссылку. Префиксы:
`fig:` для рисунка, `tab:` для таблицы, `eq:` для формулы и `app:` для
приложения. Метки уникальны, все ссылки должны разрешаться.

## Перечни

Разрешены окружения `itemize`, `enumerate`, `description` и команда `\item`.
Профиль оформляет первый ненумерованный уровень знаком `-`, а вложенные уровни —
строчными кириллическими буквами с `)` и арабскими числами с `)`. Настройка `lists.numbering = "decimal"` выбирает цифры на всех уровнях,
а `lists.marker = "en-dash"` меняет дефис на короткое тире. Маркер или
номер отделяется от текста одним неразрывным пробелом. Не вводите маркеры
вручную. Продолжения строк начинаются от левого поля.

## Рисунки

```tex
Архитектура показана на рисунке~\ref{fig:architecture}.
\begin{figure}
\centering
\includegraphics{architecture.png}
\caption{Архитектура решения}
\label{fig:architecture}
\end{figure}
```

Рисунок имеет ровно одну подпись без точки и одну метку `fig:`. Первое
упоминание обязано находиться до рисунка. Поддерживаются растровые PNG и JPEG;
SVG и TikZ не поддерживаются. `\includegraphics` не принимает необязательные
параметры 2.0.

## Таблицы

Обычная таблица использует `table` и вложенный `tabular`. Разрешены спецификация
столбцов, `&`, `\\` и `\hline`:

```tex
Результаты приведены в таблице~\ref{tab:results}.
\begin{table}
\caption{Результаты проверки}
\label{tab:results}
\begin{tabular}{|l|l|}
\hline
Формат & Результат \\
DOCX & пройдено \\
\hline
\end{tabular}
\end{table}
```

Многостраничная таблица использует `longtable`, ровно одну семантическую строку
заголовка `\tablehead{...}` и явные точки разрыва `\tablebreak`. В каждой части
между точками разрыва допускается от 1 до 18 строк данных. Для DOCX команда
начинает на новой странице отдельную редактируемую часть с надписью
`Продолжение таблицы N` и повтором заголовка. PDF размещает разрывы средствами
`longtable`, поэтому `\tablebreak` на его пагинацию не влияет.

```tex
\begin{longtable}{|l|l|}
\caption{Журнал проверок}
\label{tab:log}\\
\tablehead{Проверка & Состояние}
Структура & пройдено \\
\tablebreak
Стили & пройдено \\
\end{longtable}
```

Каждая таблица имеет одну подпись без точки, одну метку `tab:` и первое
упоминание перед таблицей. Пустая ячейка запрещена: укажите подходящее тире.
В DOCX ширина столбцов распределяется по самому длинному содержимому каждого
столбца, чтобы текст не заходил в соседние ячейки; команды ручной ширины в 2.0
не поддерживаются.
Точку `\tablebreak` ставят между строками; до сборки релизного документа следует
проверить, что каждая явно заданная часть помещается на свою страницу.

## Формулы

Разрешены окружения `equation`, `equation*`, `align`, `align*`, `aligned`,
`array`, `cases`, `matrix` и `pmatrix`. Ссылочная формула в `equation` или
`align` обязана иметь метку `eq:` и хотя бы одну `\ref`; номер добавляет
профиль. Первая ссылка должна предшествовать формуле. В ненумерованной формуле метка недопустима: для ссылки выберите `equation`
или `align`. В DOCX формулы остаются
объектами OMML; ненумерованные формулы не расходуют номера. Вокруг формул
задаётся свободное пространство. `*` и `•` в математике вызывают предупреждение
`T2S-W401`; используйте математические знаки умножения.

Математические команды 2.0: `alpha`, `beta`, `gamma`, `delta`, `epsilon`,
`varepsilon`, `zeta`, `eta`, `theta`, `vartheta`, `iota`, `kappa`, `lambda`,
`mu`, `nu`, `xi`, `pi`, `varpi`, `rho`, `varrho`, `sigma`, `varsigma`, `tau`,
`upsilon`, `phi`, `varphi`, `chi`, `psi`, `omega` и прописные варианты `Gamma`,
`Delta`, `Theta`, `Lambda`, `Xi`, `Pi`, `Sigma`, `Upsilon`, `Phi`, `Psi`,
`Omega`; операции `frac`, `sqrt`, `sum`, `prod`, `int`, `iint`, `iiint`, `lim`,
`sin`, `cos`, `tan`, `cot`, `log`, `ln`, `exp`, `min`, `max`, `det`, `left`,
`right`, `cdot`, `times`, `div`, `pm`, `mp`, `le`, `leq`, `ge`, `geq`, `ne`,
`neq`, `approx`, `infty`, `partial`, `nabla`, `mathrm`, `mathbf`, `mathit`,
`operatorname`, `text`, `quad`, `qquad`, `overline`, `underline`, `hat`, `bar`,
`vec`. `underline` допустима только внутри математики.

Пояснения символов задаются сразу после нумерованной или ненумерованной формулы окружением
`symbols`. Каждая команда `\symbol{обозначение}{пояснение}` создаёт новую
строку; профиль сам добавляет `где`, настраиваемый разделитель, точки с запятой и финальную точку:

```tex
\begin{equation}
Q = \frac{N_{passed}}{N_{total}}
\label{eq:quality}
\end{equation}
\begin{symbols}
\symbol{$Q$}{доля пройденных проверок}
\symbol{$N_{passed}$}{число успешных проверок}
\symbol{$N_{total}$}{общее число проверок}
\end{symbols}
```

## Источники

Для старых проектов сохраняется краткая пятичастная запись источника:

```tex
\source{sto}{standard}{}{СТО 02068410-004-2018}{Самара: Самарский университет, 2019. 37 с.}
```

Формат — `\source{key}{kind}{authors}{title}{details}`. Новые и уточняемые записи
рекомендуется задавать именованными полями, чтобы профиль единообразно оформлял
разные виды источников:

```tex
\begin{bibsource}
\bibkey{article2025}
\bibkind{article}
\bibauthors{Иванов И. И.; Петров П. П.}
\bibtitle{"Методы контроля"}
\bibcontributors{И. И. Иванов, П. П. Петров}
\bibcontainer{Журнал "Контроль"}
\bibyear{2025}
\bibissue{4}
\bibpages{3-9}
\end{bibsource}
```

Обязательны `\bibkey`, `\bibkind` и `\bibtitle`. Остальные именованные поля:
`\bibauthors`, `\bibmedium`, `\bibcontributors`, `\bibcontainer`, `\bibplace`,
`\bibpublisher`, `\bibyear`, `\bibissue`, `\bibpages`, `\biburl` и
`\bibaccessdate`. Тип равен `article`, `book`, `chapter`, `conference`,
`dataset`, `legal`, `preprint`, `standard`, `thesis` или `web`. Для электронных
типов обязательны URL и дата обращения; остальные обязательные поля проверяются
с учётом типа источника.

Профиль добавляет `[Текст]` или `[Электронный ресурс]`, приводит парные прямые
кавычки к `«...»`, по умолчанию использует `-` как разделитель частей записи и `–` в
числовых диапазонах. Разделитель меняется настройкой `punctuation.separator`. Источники без цитат
сохраняются в списке с предупреждением `T2S-W501`; в `--strict` оно становится
ошибкой. Поля ответственности и издания соединяются без пробелов:
`[Текст]/автор//издание`. `\cite{key}` и `\cite{key1,key2}` создают номера в
порядке первого упоминания. `\printbibliography` обязателен при наличии
источников.

## Листинги и комментарии

Окружение `verbatim` предназначено для исходного кода, прежде всего в
приложениях. Его содержимое не разбирается как LaTeX и выводится шрифтом 12 pt.
Обычные строки, начинающиеся с `%`, являются комментариями. Специальный
комментарий подавления предупреждений описан в [справке CLI](cli.md).
